# Цикл: гигиена кода (чистка без смены поведения)

Скопируй всё ниже. Укажи область: `modules/core-api`, `webui`, `scripts/vpp`, …

---

## Цель

Улучшить читаемость и согласованность в **заданной области** без изменения внешнего поведения. Лимит: **≤ 5 файлов** за итерацию.

## Чеклист (выбери 1–2 пункта за проход)

- [ ] Мёртвый код / неиспользуемые импорты (`rg` + IDE hints)
- [ ] Дублирование (DRY) в пределах одного пакета
- [ ] Имена и стиль — как в соседних файлах
- [ ] Комментарии: убрать шум, оставить неочевидную бизнес-логику
- [ ] Дрейф docs: README/spec vs факт (исправить **только** если код верен)
- [ ] `@Deprecated` без callers — кандидат на удаление
- [ ] TODO/FIXME без issue — оформить или удалить устаревшие

## Цикл

1. **Scan** — `rg "TODO|FIXME|deprecated|unused"` в области
2. **Prioritize** — безопасные удаления первыми
3. **Change** — минимальный diff, без feature creep
4. **Verify**
   - Java/Kotlin: `./gradlew.bat :<module>:test` или `buildIntegrity`
   - webui: `npm run build:js` + lint если есть
   - scripts: `pwsh -File <script> -?` или dry-run
5. **Repeat** — следующий пункт чеклиста в той же области

## Запрещено

- Массовый reformat всего модуля
- Смешивать hex-рефактор с гигиеной в одном diff
- Удалять код без проверки callers (`rg` по символу)

## Успех

- Verify PASS
- Список: что убрано/упрощено, риск «нет» или «низкий»

## Связь с hex

Если находишь legacy в application — переключись на `hex-cleanup-cycle.md`, не чини «косметикой».
